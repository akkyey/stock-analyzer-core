# Design Deepening: Polars Normal-Mapping (v4.5)

## 1. 現状のロジックと背景
`PolarsEngine` (v4.5) では、銘柄の `raw_score` をそのまま使用せず、パーセンタイル順位 (`score_pct`) に基づいて正規分布（平均50, 標準偏差15）へ射影する「Normal-Mapping」を採用しています。

### 背景
- 戦略ごとにスコアの絶対値（分布）が異なるため、スクリーニング結果の比較が困難であった。
- 正規分布に寄せることで、上位（偏差値65以上など）の定義を数学的に安定させ、ランキングの信頼性を向上させる。

### 現在の実装 (Winitzki's Approximation)
```python
def normal_map(p_col):
    p = p_col.clip(0.0001, 0.9999)
    x = 2.0 * p - 1.0
    a = 0.147
    ln_term = (1.0 - x * x).log()
    term1 = 2.0 / (np.pi * a) + ln_term / 2.0
    erf_inv = sign * ((term1**2 - ln_term / a).sqrt() - term1).sqrt()
    return 50.0 + 15.0 * (1.41421356 * erf_inv)
```

## 2. 検討すべき論点
### A. 近似精度の妥当性
Winitzki の近似式は、`erfinv` が使えない（scipy 等の非標準ライブラリを演算コアに含めたくない）環境での苦肉の策です。
- **課題**: `raw_score` が密集している中央値付近での感度が、正規分布への変換によって損なわれていないか。
- **検討**: パーセンタイルランクを用いるため、元の `raw_score` の「差の大きさ」が消失し、単なる「順位」のみが重視されるようになっている（＝順位制）。

### B. 代替案：線形マッピング
正規分布を使わず、単なる `(rank / count) * 100` （線形）にする案。
- **メリット**: 計算が単純で、理解しやすい。
- **デメリット**: 端（超優良銘柄）の差別化が弱くなる。

### C. 実行環境の制約 (`safe-shell`)
以前の ADR で記録された通り、`POLARS_MAX_THREADS=1` の制約下での CPU 負荷への影響。
- 現状の `numpy` 併用の `normal_map` は Polars Expression 内で要素ごとに呼び出される可能性があり、ベクトル化の恩恵を最大化できているか精査が必要。

## 3. 深化の方向性
1.  **実データでの分布確認**: 3900銘柄の `raw_score` と `quant_score` の相関を可視化し、正規分布化が「やりすぎ」でないかを確認する。
2.  **欠損値の扱い**: `raw_score` が `null` の銘柄が `score_pct` 計算に含まれることで、全体の平均が歪まないかの検証。
