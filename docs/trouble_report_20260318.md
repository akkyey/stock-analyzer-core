# 不具合報告書 (Trouble Report) - 2026-03-18

## 概要
Polars スキャンエンジンへの移行後、スプレッドシートへのデータ反映が極めて限定的である、または「空」に見える事象が発生。調査の結果、非同期処理のライフサイクル管理およびスコア集計ロジックに起因する複数のバグを特定した。

## 1. [Bug] CLI 実行時における DB 永続化の強制終了
- **現象**: 3,934 銘柄のスキャン完了ログが出るが、DB には数十件しか保存されない。
- **根本原因**: `src/orchestration/scan_handler.py` の `_deferred_persistence` メソッドにおいて、DB 書き込みを `daemon=True` のスレッドで実行している。
- **詳細**: CLI モードではメインプロセスが終了するとデーモンスレッドも即座に破棄される。全件の Upsert には数秒〜数十秒かかるが、その前にプロセスが終了するため、書き込みが中断されていた。
- **影響**: スプレッドシート（DB 経由）のデータが壊滅的に不足する。

## 2. [Bug] Polars エンジンにおけるスコア内訳の欠落
- **現象**: 保存されたデータも `Fundamental` スコアが `0.0` または `Summary` の内訳が空になる。
- **根本原因**: `src/calc/engines/polars_engine.py` が `quant_score`（合計値）のみを出力し、レポーターが期待する `score_value`, `score_growth`, `score_quality` 等のカラムを出力していない。
- **影響**: 詳細レポートの分析精度が著しく低下して見える。

## 3. [Observed] RSI データ取得の網羅率（約 50%）
- **現状**: CSV レポート上の RSI カバー率は約 50% 程度。
- **原因**: 1 ヶ月分の履歴データ取得（yfinance）において、レートリミットや接続タイムアウトによる失敗が散発している。
- **対策状況**: マッピングバグは修正済みであり、計算に成功した銘柄は正しく表示されている。網羅率の向上には Fetcher 層のリトライ強化が必要。

## 今後の対応案 (Next Steps)
1. **永続化の修正**: `daemon=True` を解除し、CLI 終了前に書き込み完了を保証する。
2. **スコア集計の強化**: `PolarsEngine` に `METRIC_CATEGORY` ベースの集計ロジックを実装する。
3. **網羅率向上**: YahooFetcher のエラーハンドリングとバックオフの導入。
