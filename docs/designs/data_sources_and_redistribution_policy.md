- **作成日**: 2026-10-06
- **ステータス**: **決定・適用済み**（v1.3.1 にて方針 (b) を採択。出所未確認の 16 列をすべて None で上書きし、新シード識別子 `e3f635c30bb9` を確定。既存 DB では、`sales_growth` を除く 15 列の旧値が維持される）
- **対象ファイル**: `src/resources/fundamentals_seed.parquet`（同梱の財務データ。以下「シード」）、`scripts/build_fundamentals_seed.py`
- **注意**: 本書は、法的な助言ではありません。利用規約の確認結果と、コード・コミットから確認できた事実を記録し、公開前に、利用者（リポジトリの所有者）が最終判断するための資料です。

## 1. 背景

シードは、ツールのコード本体と一緒に配布する（同梱する）財務データの初期セットで、初回実行（DB が空）のときに自動で読み込まれる。公開リポジトリに入れるデータなので、**出所と利用条件**を確認し、条件を守れない列は入れないことが必要になる。2026-10-06 に、シードを EDINET から作り直した際に、次の疑問が出たため、確認結果を記録する。

> このシードは、EDINET や yfinance から作られたものだと思うが、同梱して問題ないか。

## 2. データ源と利用条件

| データ源 | 利用条件（確認した内容） | 本ツールでの使い方 | 同梱の可否 |
| :--- | :--- | :--- | :--- |
| **EDINET**（金融庁）の有価証券報告書・半期報告書 | [EDINET 利用規約](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/WZEK0030.html)。「公共データ利用規約（第 1.0 版、PDL1.0）」に従えば、誰でも利用できる。**出典の記載が必要**（「出典：EDINET 閲覧（提出）サイト（URL）、PDL1.0（規約原文の URL）」）。加工した場合は、「EDINET 閲覧（提出）サイト（URL）をもとに〇〇作成」の記載も必要。**「国が作成した未加工のデータであるかのような態様で公表・利用してはいけない」**。スクレイピング等の機械的な取得は禁止だが、**API の利用は対象外**（ただし、短時間の大量のアクセスは禁止）。ロゴ・EDINET タクソノミ等は規約の対象外。**提出企業の著作権については、規約に記載がない** | API で、書類の一覧と XBRL を取得し、財務の数値（事実）を抽出する。シード作成は、5,032 件を 97 分（一覧の並列 10、ダウンロードの並列 2）で取得。実行は年 1 回ほどの想定 | **条件付きで可**。出典・加工の記載が必要（現状は未記載。T-02）。財務の数値（事実）を扱う限り、著作権上の問題は生じにくいと考えるが、規約に明記はないため、最終判断は所有者による |

### 2.1 JPX の上場銘柄一覧の利用条件（2026-10-10 に確認・決定済み）

確認した規約（[サイトのご利用上の注意と免責事項](https://www.jpx.co.jp/term-of-use/index.html)「免責事項・著作権等について」→「全般」）の原文:

> 当サイトに掲載されている情報について、有料・無料を問わずJPXからの許諾を得ている場合を除き、商用目的によるデータ収集のほか如何なる用途に関わらず二次利用及び再配信はできません。

- 一覧のページ（[東証上場銘柄一覧](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html)）には、利用条件の個別の記載は無く、免責事項のみ。サイトの規約が適用されると読める。
- **決定: JPX の一覧は、同梱しない。** 利用者が、自分の環境で、実行時に JPX から取得する（元々、同梱は想定していなかった）。
- 対応（2026-10-10）: `src/resources/jp_stock_list.csv`（`code,name,sector,market`・3,926 行）をリポジトリから削除し、`src/fetcher/jpx.py` の同梱ファイルの読み込みを外した。同梱なしでも、JPX から直接取得できること（3,890 銘柄）を確認した。
- **注意**: 削除前のコミットには、このファイルが残っている。履歴は、初版公開時にリセットする方針（レビュー票 T-00・T-07）に従う。履歴を残したまま公開する場合は、履歴に JPX の一覧が残ることになる。
- 実行時に、利用者が JPX から取得して、手元の `data/input/jp_stock_list.csv` などに保存し、レポートに社名・業種・市場を出す点は、利用者自身の取得であり、同梱とは別の扱い。ただし、規約の文言（「如何なる用途に関わらず二次利用…はできない」）との関係は、所有者が最終判断する。
- JPX に接続できない環境では、初回の実行が、銘柄マスタを作れず失敗する（同梱の代替が無くなったため）。

本書は法的な助言ではありません。規約の文言からの読み取りであり、最終判断は所有者が行ってください。

## 3. シードの列ごとの出所

シード（3,926 銘柄）の列を、出所で分類する。**EDINET 由来**は、パーサーが XBRL から読んだ値（コードで確認済み）。**出所未確認**は、旧シードから引き継いだ列で、取得処理がリポジトリに無く、**由来を確認できない**。

### 3.1 EDINET 由来（確認済み）

| 列 | 内容 | 備考 |
| :--- | :--- | :--- |
| `sales`・`operating_income`・`net_profit`・`prev_net_profit` | 売上・営業利益・当期純利益・前期の純利益 | 有価証券報告書の要約表・財務諸表本体 |
| `eps`・`bps`・`dps` | 1 株当たりの利益・純資産・配当 | 要約表。ガード（株数との整合）あり |
| `net_assets`・`shares_outstanding`・`equity_ratio`・`roe` | 純資産・発行済株式数・自己資本比率・ROE | 株数は、提出日現在の値を優先 |
| `operating_margin` | 営業利益率 | 売上・営業利益から計算（EDINET の値の派生） |
| `period_end`・`submitted_at`・`bs_period_end`・`bs_submitted_at` | 値の出所（決算期・提出日時） | 取り込みの記録 |

### 3.2 出所未確認（旧シードから引き継いだ列）

旧シードの非空の件数（原本 3,912 銘柄）。新シードも、同じ値を引き継いでいる。

| 列 | 件数 | 足切り・採点での使用 | レポート出力 |
| :--- | :--- | :--- | :--- |
| `operating_cf` | 1,755 | **使用**（`pre_filter.py`: 営業 CF マージンの足切り。空のときは判定を省く） | なし |
| `free_cf` | 667 | なし | なし |
| `payout_ratio`・`payout_status` | 1,754・1,760 | なし | なし |
| `current_ratio`・`quick_ratio` | 1,740・1,740 | なし | なし |
| `debt_equity_ratio` | 1,459 | なし | なし |
| `sales_status`・`profit_status`・`is_turnaround`・`turnaround_status` | 各 1,760 | なし | なし |
| `profit_growth`・`profit_growth_raw` | 1,587・1,268 | `profit_growth_raw` は評価時に再計算される箇所あり（要確認） | `Profit_Growth` |
| `sales_growth` | 旧 1,612 → 新 1,418（売上が変わった 194 銘柄は空） | なし | `Sales_Growth` |
| `repair_metadata` | 3,741 | なし | なし |
| `fetch_status` | 3,912（`edinet_synced` 3,741・`unfetched` 171） | なし | なし |

**出所についての手掛かり（どちらとも断定できない）**
- 列名が、yfinance の財務項目（`currentRatio`・`quickRatio`・`debtToEquity`・`operatingCashflow`・`freeCashflow`・`payoutRatio`）と対応している。コードの注記に、以前の版が yfinance の財務を使っていたことを示す記述がある（「v10: yfinance financials 排除」）。
- 一方、旧シードの `fetch_status` は、3,741 件が `edinet_synced` で、コミット `e087f8d`（2026-09-30）に「**Clean 171 unverified non-EDINET rows** in fundamentals_seed.parquet」とある。EDINET 以外の行を除いた記録で、残った行は EDINET の取り込みを経ていた可能性がある。
- 旧シードの生成手順は、リポジトリに無い（最初のコミット `f4d83b4` から、ファイルとして追加されている）。**旧シードを作った方に、作り方を確認する必要がある**（T-01）。

### 3.3 株価依存の列（空）

`per`・`pbr`・`dividend_yield`・`market_cap`（全件空）。実行時に、当日の株価から計算する。

## 4. 方針の決定と適用結果

1. **同梱するのは、出所が確認できるデータだけ**にする。3.1 の EDINET 由来の列は、同梱する。
2. **3.2 の出所未確認の列は、すべてシードから外した（空にした）**。影響は小さい: 足切りに使われるのは `operating_cf` だけで、空のときは、その判定を省くだけ（新規環境）。レポートの成長率列（`Sales_Growth`, `Profit_Growth`）は `-`（欠損）として出力される。
   - `operating_cf`, `sales_growth` 等を含む全 16 列を None で上書きし、シード識別子 `e3f635c30bb9` として確定した。
   - 既存 DB を持つ環境では、空の値で上書きしないため、旧値が保持される。ただし `sales_growth` だけは、シードの売上が更新される銘柄で、財務データの更新時に空になる（売上が変わると、旧い売上との比較が成り立たないため）。
   - その結果、既存 DB と新規 DB で、営業 CF の足切りと `Profit_Growth` の表示が異なる（既存 DB は旧値が残る）。
3. **出典・加工・非公式の明記**: README と利用ガイドの免責の章に、次を記載（T-02 で適用済み）。
   - 「出典：EDINET 閲覧（提出）サイト（<https://disclosure2dl.edinet-fsa.go.jp/>）、公共データ利用規約（第 1.0 版）」
   - 「EDINET 閲覧（提出）サイトをもとに、akkyey（本プロジェクト作成者）が加工して作成」（財務の数値を、XBRL から抽出し、一部を計算した旨）
   - 本ツールが、金融庁・東証・Yahoo! のいずれにも、**関係せず、公式のものではない**旨。株価データは、Yahoo! Finance から、利用者が自分の環境で取得する旨（同梱していない）。
   - 同梱の財務データを、**国が作成した未加工のデータとして誤認させない**表現にする。
4. **再作成の頻度**: シードの作成は、EDINET API への負荷（97 分、5,032 件）を考え、**年 1 回ほど**（6 月の提出が一巡した後）に留める。利用者の実行は、同梱のデータと、直近 30 日分の差分の取得だけで済む。
5. **公開リポジトリに含めないもの**: `.env`（API キー）、個人のテスト用ファイル、個人の PC のパス（レビュー票 T-03・T-07）。
